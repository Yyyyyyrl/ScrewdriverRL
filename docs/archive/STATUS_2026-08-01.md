## 4. 掉落率 0% → 20% 的根因（已定位，未验证修法）

**排除**：turn 权重（带力版用**完全相同**的 120/170/200）、缺掉落惩罚（带力版**也没有**）。

**真正差异 —— 力→距离替换丢失了握力的可感知性**：

| 项 | 带力版 | 当前版 |
|---|---|---|
| grip | `w_grip × engage`（**力窗口**） | `w_grip × distance_score`（**距离**） |
| excess | `excess_force(F_total, f_max)`（实际过力） | `target_penetration(...)`（目标穿透代理） |
| wrong | `w_wrong × wrong_force`（力的**大小**） | `w_wrong × wrong_surface_present`（**二值**） |

**机制**：一旦接触，**距离即饱和**（clearance≈0），而力仍可从"刚碰到"变到"死死捏住"。
策略在最关键的区间失去分辨能力，也没有奖励引导它握稳。`wrong` 从连续量退化为二值同样丢梯度。

**另一个已知差距**：训练量。带力版 **300M 步**，3 帧 ep330 仅 **57M**。

**当前代码中另有一处结构性隐患**（本轮新发现，带力版无此参数）：
`reward_turn_weight` 随 phase 放大（120→170→200），而 `reward_reverse_weight` 是全局常量 220，
故前/后比 0.55→0.77→**0.91** —— **防振荡保护恰在转动压力最大时最弱**，与 Phase 3 的
OscRatio 0.44 吻合。已做的缓解：`-Hora` cfg 中把 phase3 的 turn 权重降为与 phase2 相同（170）。

## 7. 重要的工程约束与已踩的坑（务必遵守）

1. **单张 24GB GPU，绝不并行跑训练与 eval** —— 会抢显存并诱发挂起。
2. **所有长任务必须 `setsid` 启动**：
   ```bash
   setsid nohup env PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True <python> train.py ... \
     > run.log 2>&1 < /dev/null &
   ```
   普通 `cmd &` / `nohup &` / 挂在监控脚本下的子进程，都会在父进程或工具调用结束时被回收，
   **现象是打印完启动横幅就静默消失、日志无报错**，极易误判为崩溃（本轮以三种形式各踩一次）。
3. **启动后必须验证关键参数真的生效**（读日志里的 pinned/契约行），不能只看"进程起来了"。
   本轮 `--stage2_phase 1` 曾未生效而未被发现。
4. **Isaac 会间歇性挂起**（~15 分钟到 1 小时不等，无 traceback）。用
   `tools/supervise_hora_full_training.py`，`--stall-seconds 300`（**必须 > 启动耗时 ~5 分钟**，
   否则每次启动都被杀成死循环）。已给它加 `_log_has_training_progress()` 前提。
5. **epoch → 步数换算**：每次 resume 会**重置 epoch 计数**。第三个 run 目录自 13,762,560 步
   resume，故真实步数 = `13,762,560 + ep×131,072`（131072 = 4096 envs × 32 horizon）。
   本轮曾因此选错全部候选。
6. **度量口径**：训练日志 `NetTurns` = **授权**净转（`eval_net_turns`）；eval 的
   `net_turns_mean` = **物理**净转（`eval_raw_net_turns`）；与训练可比的是
   `authorized_net_turns_mean`。**不可混比。**
7. **`--eval_phase` 默认 `final`（Phase 3）**。评估 Phase-2 训出的 checkpoint 必须显式
   `--eval_phase 1`，否则是在它撑不住的口径下评判。
8. **契约类改动必须在 train / eval / deploy 三条路径各跑一次**。本轮只验证 train+deploy，
   导致 eval 路径两个 bug（`proprio_dim` 未同步、帧堆叠读到冻结缓冲）都漏到很晚才发现。
